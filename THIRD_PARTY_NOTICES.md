## Third-party inventory

This inventory is maintained with the repository and audited whenever build or runtime dependencies change. It distinguishes material incorporated into a distributed artifact from tools that merely run on the build or test host. License compatibility here means that the identified material can be conveyed in or alongside a `GPL-3.0-or-later` promptboot distribution while its own license and notices remain in force; it does not mean that third-party material is relicensed as GPL.

The audit found no known GPL-3.0-or-later incompatibility in the tracked or released material. The exact applicable texts are tracked under `LICENSES/` and are conveyed with both the release directory and bootable FAT image.

## Release treatment

Every release contains the project GPLv3 text, this inventory, and the exact Qwen, llama.cpp, libm, Rust `core`, and Rust `compiler_builtins` texts at its outer root. The bootable FAT16 image carries byte-identical copies using FAT-compatible names under `/LICENSES`, plus `/LICENSE`.

`SOURCE.TGZ` is a deterministic `git archive` of the exact recorded release commit. It is also embedded in the FAT image. Release verification checks its commit-derived prefix, tracked-file membership, bytes, and SHA-256 and rejects a dirty worktree. Keep the release directory together when conveying it or writing its image to USB.

QEMU, OVMF, host toolchains, and the cached llama.cpp build are not included in the release. `MODEL.PBT` is explicitly a modified/repacked form of the pinned Qwen model; the source archive preserves the fixture-family provenance above.

Primary compatibility references are the [FSF license list](https://www.gnu.org/licenses/license-list.html#GPLCompatibleLicenses), which specifically classifies Apache-2.0 as GPLv3-compatible, and the [GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html#WhatIsCompatible), which distinguishes combining code from merely installing or using separate programs.
